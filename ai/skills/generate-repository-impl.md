# generate-repository-impl.md
## Repository Implementation Generation Specification
Version: 1.2

This skill defines how the AI development agent must generate repository implementations
for a Java 25 + Spring Boot project.

---

# 1. Goal

Generate the infrastructure-side implementation of a domain repository using
Spring Data JPA and PostgreSQL only.

---

# 2. Rules

Repository implementations MUST:
- live in infrastructure
- implement domain repository abstractions
- isolate Spring Data/JPA concerns from the application and domain layers
- support pagination and filtering when required
- use PostgreSQL only
- assume PostgreSQL latest as the single supported database
- use UUID identifiers in repository contracts and persistence entities

Repository implementations MUST NOT:
- leak JPA entities to the application layer
- place business rules inside persistence code
- generate compatibility code for any other database engine

---

# 3. PostgreSQL Policy

All repository implementation templates, queries, mappings, and integration tests
must target PostgreSQL exclusively.

The generator MUST NOT create:
- alternative SQL dialect branches
- H2-specific tests
- MySQL/MariaDB/Oracle/SQL Server compatibility code
- database-agnostic fallbacks when they reduce PostgreSQL fidelity

When database-specific behavior is needed, PostgreSQL behavior is the source of truth.

---

# 4. Identifier Policy

Repository implementations must assume:
- domain ids are UUID
- persistence ids are UUID
- table ids are generated by PostgreSQL with `uuid_generate_v4()` defaults

The agent must not generate numeric identifier mappings.

---

# 5. Testing Rules

Integration tests must validate against PostgreSQL behavior only.

---

# 6. Minimum Acceptance Criteria

A generated repository implementation is valid only if:
- it respects the domain abstraction
- it isolates infrastructure concerns
- it uses PostgreSQL/Flyway conventions
- it uses UUID identifiers consistently
- it does not introduce support for any other database
